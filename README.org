#+TITLE: vtx

This is both a library for terminal emulation and a terminal emulator and
multiplexer built on top of it.

*libvtx* implements the VT100 protocol plus some extensions. It is an
abstract terminal, not the real thing: it parses what a program writes to a
pty and keeps a grid of cells and faces, and turns a key event into the
bytes a real terminal would send. It doesn't open a pty, read a keyboard, or
draw anything, and it doesn't know what uses it. Package is =libvtx=,
nicknamed =vt=.

*vtx* is a terminal emulator and multiplexer built on top of libvtx. It can
manage several sessions at a time, each maintaining a tree of windows and
panes from a server, so a client can attach, switch, or detach, and come
back later with its layout and state intact.

** Building

#+begin_src sh
make test        # the whole suite
make test-term   # libvtx alone
make vtx         # the binary
#+end_src

Guix is what this develops against. Without it, put =FOREIGN=1= in front and
it uses whatever SBCL is already on the machine:

#+begin_src sh
make FOREIGN=1 test
#+end_src

libvtx has no dependencies. vtx needs =sb-posix= and =sb-bsd-sockets=, both
part of SBCL, and FiveAM for its own tests.

** Installing

vtx, straight from this tree:

#+begin_src sh
make FOREIGN=1 install                       # PREFIX=/usr/local
make FOREIGN=1 install PREFIX=$HOME/.local
#+end_src

Or, if one of these is already around:

#+begin_src sh
ros install bretfhorne/vtx
brew install bretfhorne/vtx/vtx
guix install vtx
#+end_src

A tagged release also carries a Linux AppImage and a macOS tarball.

libvtx, on its own:

#+begin_src sh
ocicl install libvtx
#+end_src

** Extending libvtx

A term is a struct. Add a sequence, or change what one means, from outside
this repo:

#+begin_src lisp
(defstruct (my-term (:include vt:term)))

(defmethod vt:handle-csi ((term my-term) (final (eql #\A)) format params)
  (my-cursor-up term (or (first params) 1)))
#+end_src

No macro, no registry. =defmethod= is the extension point.
