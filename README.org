#+TITLE: automatty

automatty is both a library for terminal emulation and a terminal emulator and
multiplexer built on top of it. The command is =atty=.

*libatty* is an implementation of the VT100 protocol plus a growing set of
others to serve modern needs. It provides an abstract model that parses what
a program writes to a pty and keeps a grid of cells and faces, and turns
input into the bytes a terminal would send.

*atty* is a terminal emulator and multiplexer built on top of libatty. It can
manage several sessions at a time, each maintaining a tree of windows and
panes from a server, so a client can attach, switch, or detach, and come
back later with its layout and state intact.

The server also knows what the program in each pane is doing. It holds every
pane as a grid of cells, not a stream of bytes, so it can tell a coding agent's
prompt box from its permission dialog from its spinner, and it says so on the
bar and over the socket. =atty agent list= names every pane and whether it is
idle, working or blocked. =wait= blocks until one is. =read= answers what is on
its screen, as text. =prompt= gives it new work, =say= answers what it is
asking, and =explain= names the rule that decided. A program inside a pane can
say its own state with =atty agent signal=. There is nothing to install and no
protocol to speak: an agent that can run a shell command can watch another
pane, wait until it is stuck, read why, and answer it, through the terminal it
already has.

** Installing atty

atty is one file. A release carries it built for each platform, with a
=SHA256SUMS= to check it by:

#+begin_src sh
curl -fsSL https://github.com/bretfh/automatty/releases/download/v0.1.0/atty-v0.1.0-darwin-arm64.tar.gz | tar xz
./atty                        # or put it somewhere on PATH
#+end_src

The names are =atty-<tag>-darwin-arm64=, =-darwin-x86_64=, =-linux-x86_64=. The
linux one is built on Ubuntu 22.04 and runs on any glibc since; on musl (alpine)
build it from source. A file a browser downloaded on macOS carries a quarantine
flag, and =xattr -d com.apple.quarantine atty= clears it; one curl fetched
carries none. The binary is signed by nobody: there is no notarization, which
takes an Apple developer account.

From source, on a machine with sbcl on it (=brew install sbcl= on a mac; the
distribution's sbcl on linux):

#+begin_src sh
make FOREIGN=1 deps install                   # PREFIX=/usr/local
make FOREIGN=1 deps install PREFIX=$HOME/.local
#+end_src

Or, on guix, =guix package -f guix.scm= from a checkout, or add this repository
as a channel and =guix install atty=. With roswell, =ros install bretfh/automatty=.

*** Staying current

#+begin_src sh
atty version                  # which build this is, and the server's when it is another
atty update --check           # whether a newer release is out
atty update                   # put it where this atty is, and restart the server from it
#+end_src

=atty update= replaces the file it is running from, so it works where the file
is yours: a tarball you put on PATH, or =make install PREFIX=$HOME/.local=. Where
a package manager put it (brew, guix, nix, apt) it says what that manager's
upgrade is instead, and =atty restart-server= afterwards moves the running server
onto the new build. Either way the server keeps every session, window and
pane: they are on disk (see below), and each terminal attached waits for the
new server and becomes the new build itself, on the same session it was on. The
server asks once a day whether a release is out and says so to the next
terminal to attach; =(configure :check-for-updates nil)= in init.lisp stops it
asking.

** Building

For working on this repo:

#+begin_src sh
make test                     # the whole suite
make test-term                # libatty alone, nothing else loaded
make run CMD='top -b -n 1'    # run a command on a pty, print the screen libatty drew
make atty                     # the binary, in this directory
make release                  # the binary as a release tarball, in dist/
#+end_src

This is developed on Guix, where =manifest.scm= names what it needs. Without
guix, =ocicl.csv= pins the same lisp systems and =make FOREIGN=1 deps= fetches
them into =ocicl/= with curl and tar (=deps.lisp=; the ocicl program is only
needed to change what is pinned); then =FOREIGN=1= in front of any target uses
whatever sbcl is on the machine:

#+begin_src sh
make FOREIGN=1 deps test
#+end_src

Either way sbcl runs without your init file and sees this directory and the one
place the dependencies are, so nothing in a home directory reaches a build.

** Using atty

#+begin_src sh
atty                    # a shell, in a session called 0, made if it isn't there
atty <name>             # the same, under another name, started where you are
atty attach [<name>]    # join a session already running
atty list               # the sessions: windows, panes, what needs you, who is attached
atty clients            # every terminal attached, and what each is looking at
atty rename <old> <new> # call a session something else
atty stop <name>        # stop a session, and the programs in it
atty kill-server        # stop every session
atty -L <server> ...    # any of these against a server other than your own
#+end_src

One server holds every session, the way tmux's does. A session holds windows,
a window holds panes in their splits, and each terminal attached is a client
looking at one window of one session. A pane's address is
=session:window.pane=, =todo:1.2=: window 1 of todo, its second pane.

=^-b= is the prefix for everything else, and the one key to learn: press it
and wait, and a menu rises from the foot with every key that can follow,
grouped by what it acts on, with no timeout. Type straight through and it
never shows. Every key runs a named command, and =^-b := lists them all with
their keys and a line on each, so any can be bound to something else; =^-b ?=
is the same list grouped by what they act on, and =?= on anything that is up
lists that thing's keys.

Everything drawn on top of the panes has the same shape: a header saying what
it is and where you are with =✕= at its right, a toolbar of its controls with
their keys printed on them, a gutter of marks down the left, a rail down the
right when there is more than fits, and a footer of keys that are buttons.
Escape closes any of it. Every rail is drawn the same way: a thin line is the
whole length, a heavy line is the part in view, and its ends are lit only when
there is more that way. This terminal is =◆=, another terminal is =⌨= and its
tty, a pane that typed into another is =⌁= and its address, and the command
line is =$=. Anything that wants a word from you, a name or a yes, takes the
one line at the foot where the keys are, and never covers the screen.

#+begin_src sh
^-b c   ^-b n   ^-b p   # a new window; the next; the one before
^-b '                   # every session › window, the ones asking first; RET goes, C-RET makes a window there, TAB its panes
^-b ,   ^-b .   ^-b $   # name this window; name this pane (TAB swaps between them); name this session
^-b &                   # close this window and every program in it, after a yes
^-b C                   # another session
^-b 2   ^-b 3   ^-b 0   ^-b 1   ^-b o   # split below; split beside; close this pane; only this pane; the next pane
^-b d   ^-b D           # detach; who is attached, to go to what they see, follow one, or detach one
#+end_src

The bar lists this session's windows, lit where you are, yellow with a count
where a pane is asking something, and a =+= that opens one. Then the field
that opens the palette, what needs you anywhere, the other sessions, who else
is attached (=←= after one that follows another), =^-b menu=, and the time.

The palette is one prompt with four tabs: =:= the commands, =@= every
session › window with its panes previewed beside, =#= the terminals
attached, =/= find in this pane with the hits listed as you type. =^-b :=,
=^-b '=, =^-b D= and =^-b /= open them; typing another tab's prefix first
switches to it, and TAB goes round them. In =#=, =C-f= follows the terminal
chosen: this one shows whatever session that one shows, as it moves, until
you type something of your own.

Every pane's frame is the colour of what its program is doing: working,
blocked or idle, with how long; the pane with the focus has a heavy border and
the others a thin rounded one. A pane that is asking something carries the
question in its top border and its answers in its bottom one; click one to
answer.

#+begin_src sh
^-b N                   # what needs you: every question, where it is, who is looking at it; a digit answers
^-b w                   # the switchboard: the whole server. A side pane beside a lane for every session; - and + zoom
                        # out to a row of chips a session and in to one session; \ hides the side pane, / filters
^-b a                   # go to whatever has been blocked longest
^-b e                   # why a pane is what it is: what it is, its state, how it was read, who typed there; answers at the foot
^-b z                   # zoom a pane
#+end_src

On the switchboard every session is a lane: a header with its name, its
counts and =+ window=, its windows as boxes showing their panes' last lines
(a split window divides its box with a dotted rule naming the pane under
it), and a foot that is the lane's scrollbar and says which windows are in
view. The box with the cursor has a heavy border in its state's colour and
carries its answers and =↵ go= in its bottom edge; the lane with the cursor
lists the lane's keys on its foot (=← →= window, =c= new window, =r= rename
the session, =⇥= fold);
the footer lists only the keys that work anywhere (=↑↓= session, =n= the
oldest question, =- += zoom, =/= filter, =\= side pane). On the box: =x=
closes, =,= names, =p= prompts, =SPC= picks for a prompt to several, =e=
opens the details drawer, a digit answers. The side pane shows what is going
on everywhere: the server, every session and the cursor's session's windows
each with a sparkline of the last twenty minutes (height is how much was
written, colour is the most urgent state then: asking outranks working
outranks idle; a shell is grey), an activity log of what just happened across
the server (questions, answers and who gave them, typing, programs starting
and finishing; the wheel scrolls it and a click on a line puts the cursor on
that window), and who is attached. =atty events= prints the same log.

The mouse works everywhere: chips on the bar, the menu, answers in a frame,
rows in a prompt, boxes, lanes and rails on the switchboard, questions on the
needs-you list, the answers at the foot of the drawer. In a pane it works the way it
would with nothing in between: a program that asked for it gets the wheel and
the buttons; one with the whole screen gets the wheel as arrow keys; anything
else has its pane read back.

#+begin_src sh
^-b [                   # read back from the keys: arrows or j k, PageUp PageDown, ^-u ^-d, g G; q leaves
^-b /                   # find in the pane's history; n and N move between the hits, which are lit
v  y                    # in reading back: mark the top line; copy from the mark to here (or the screen) to the clipboard
#+end_src

While a pane is read back its frame says how far from live, which hit this is,
and carries a =⌕ find= button; a click on the =↓ N to live= chip is back to
live.

These are defaults. =~/.config/atty/init.lisp= (or under =$XDG_CONFIG_HOME=)
is loaded when atty starts, in the client and in the server, from source. It
binds a key, a button or the wheel to any command by name, defines commands,
sets settings, and hooks what happens:

#+begin_src lisp
(define-key 'pane-mode "M-wheel-up" "scroll page up")
(undefine-key 'pane-mode "C-b t")
(defcommand say-hello (show-note *client* "hi" "hello"))
(configure :prefix "C-a" :wheel-rows 6 :theme :ef-dream)
(add-hook 'pane-started (lambda (session pane) ...))
#+end_src

=atty help init= lists every setting with what it is now. A file that does not
load is said in the log and shown as a note to whoever attaches next; atty
starts anyway. =^-b R= loads it again without restarting.

** What is kept when the server stops

Everything the server holds goes to =~/.local/state/atty/<server>/= (or under
=$XDG_STATE_HOME=): the sessions, their windows and the splits in them, and
what every pane holds, screen and scrollback with their colours, its log, what
it ran and where. The tree is written whenever it changes, each pane when it
has been quiet a moment, and everything when the server stops, whether asked
or by a signal.

A server started on the same name brings it all back before it answers
anybody. Each pane shows what it showed, with a rule under it saying when it
was brought back, and its program starts again under the rule: a shell in the
directory it was in, and for anything else, an agent say, a shell standing in,
the rule saying what was running (=(configure :restore-command :same)= restarts
it instead). Everything that was behind the screen is still behind it.

#+begin_src sh
atty restart-server     # stop it and start it from this build, keeping everything; clients wait and come back
atty save               # write it all now
atty list               # says what is saved when nothing is running
atty start --fresh      # start with nothing; what was saved is moved aside, not deleted
#+end_src

The same from a shell, for a program driving other panes:

#+begin_src sh
atty agent spawn work --name impl -- claude    # a pane beside the focus; prints work:1.2
atty agent spawn work --new-window -- claude   # in a window of its own; --window 2 puts it in that one
atty agent list --blocked                      # or --json, --session <name>; each with its window
atty agent read work:1.2 --plain               # its screen, without what is only suggested
atty agent answer work:1.2 1                   # exits 3 if it is asking nothing
atty agent prompt work:1.2 'run the suite'
atty agent wait work:1.2 idle --after-prompt   # only once it has taken the prompt up
atty agent log work:1.2                        # who typed into it: a client, a pane, the command line
#+end_src
