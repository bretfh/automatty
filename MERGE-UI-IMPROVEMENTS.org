#+TITLE: Merging ui-improvements with the agent architecture

* Where the two lines of work stand

Both start from ~0513605~.

- *main, uncommitted:* the agent architecture in [[file:AGENT-ARCHITECTURE.org]]. It covers process recognition from the kernel, readers as versioned data with recorded corpora, sessions with turns and reasons, typed actions confirmed on the screen, the catalog with live update, the Claude 2.1.278 and Cursor 2026.09.18 readers, and the macOS make targets.
- *ui-improvements, 12 commits:* ~PLAN.org~. That's one server per user, frames coloured by state carrying the question and answers, needs-you, the switchboard, the explain drawer, and a CLI that does what the UI does.

Both reworked the agent layer. The UI branch extended the old rule tables. main replaced them.

* The principle

The UI keeps everything it shows and every command it offers. The agent API it calls is served by the new session layer. Its screen parsing (~asks-of-lines~, the ~agent-doing~ method on ~claude-code~, ~without-spinner-tail~) is superseded by widgets and reader data. Where that parsing does something the widgets don't, the behaviour moves into a widget or a reader rather than being lost.

* The API the UI calls, and what serves it

| UI calls | Uses | Served by after the merge |
|---+---+---|
| ~agent-state~ | 16 | unchanged |
| ~agent-asks~ | frames, panes | the current observation when it means ~:blocked~: ~(:subject (first subject) :detail (rest subject) :question … :options … :chosen selected)~ |
| ~agent-doing~ | panes | the spinner widget's label while working. When idle, the last line the agent said, from a new ~said~ widget whose marker (Claude's ~⏺~) is reader data |
| ~agent-for~, ~agent-history~, ~agent-since~ | frames, bar, panes | ~became~ added to the session: every state change stamps ~since~ and pushes history |
| ~agent-known-p~ | frames, panes | a reader is attached, or the program has signalled |
| ~agent-won~ | frames | the observation's ~:screen~ id |
| ~agent-explain~ | server, drawer | rows become ~(id widget means won seen)~; ~explain.lisp~ prints those |
| ~lines-of~ | main, explain | re-added to ~screen.lisp~ and exported |
| ~agent-become~, ~make-agent~ | pane | keyword arguments (~:title :command :programs :paths~) |
| ~agent-look~, ~agent-hear~, ~agent-prompted~, ~agent-trace~, ~last-lines~, ~screen-lines~, ~screen-blocked-p~ | server, panes | exist with the same meaning |

* Where the two found the same things

The branch's ~3b9f2c6~ and main's field rerun found the same two problems independently: a pasted prompt isn't taken as an instruction, and a tip isn't what a dialog asks about.
